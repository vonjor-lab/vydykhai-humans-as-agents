# Context Routing Review

Candidate: 1.26.0. Scope: universal framework contracts and offline validation; no project repair, memory migration or live experiment.

## Evidence And Limits

Three bounded cases were inspected through existing task contracts, current memory and durable execution receipts. They are sanitized below. Their historical receipts are observations, not a new independent replay. Where the pre-change brief was unavailable, a retrieval failure is not asserted. No evidence establishes that memory alone caused every reported product failure.

| Case | Observed boundary | Required context route | What this does not prove |
| --- | --- | --- | --- |
| Shared catalog selection | A source repair corrected selected-item meaning and reference delivery; real data and live consumer acceptance remained open. Current memory was subsequently clarified with the wider consumer contract. | User outcome -> catalog identity/ownership -> prior accepted selection mechanism -> rendering, persistence and calculation consumers -> scoped verification. | Actual data deletion or the precise original retrieval failure; a source-only fix is not complete product restoration. |
| Persistent conversation | A contiguous handler check found that domain evidence could be published before a required conversation turn failed. Isolated green checks had not established the combined transaction. | Reopenable user journey -> canonical state/transaction ownership -> existing publication and turn contract -> same-request success/rollback/reload. | Merely adding a graph link fixes transaction code, or all earlier instructions were absent. |
| Demo/runtime boundary | A real adapter check exposed an interface mismatch missed by lower-level fixtures. A separate isolated-runtime preparation correctly stopped when different ports still shared bootstrap and storage. | Actor scenario -> exact runtime/data/adapter contract -> actual boundary verification; for parallel startup also shared-resource ownership -> allowed isolation path. | Every stop is a memory miss. The justified stop is a negative control that must remain safe. |

A later bounded catalog follow-up observed a proposed request for replacement input after an empty local view. A human correction identified previously accepted shared sources; the request was withdrawn and source recovery was assigned. This supports distinguishing not found, inaccessible, incompatible consumer and proven loss. It does not establish that data was deleted, preserved or recovered, and is not a new live success test.

## Smallest Supported Change

- Replace fixed seven-node/two-hop truncation with complete applicable goal-to-evidence routing in the existing Memory Brief.
- Require the same route at shaping, correction and acceptance, with original-source review where important qualifications are unproven; retain role boundaries and hot-path continuation.
- Fix the deterministic checker: missing node fields, dangling references and `PASS` in the wrong table column previously escaped validation. Offline first-fail/pass tests cover those defects and a graph with more than seven relevant records.
- State the limit explicitly: structural validity does not establish semantic completeness or live behavior. A candidate migration must replay source-backed questions with a fresh evaluator before coverage is accepted.

The remaining project-level evaluation is the side-by-side inventory and replay described in [Context Route](workflows/context-route.md). No reduction in real-project failure rate, token use or task duration is claimed before that evaluation. Do not use the sanitized cases as fabricated live success receipts.

## Preparation And Lifecycle Review

| Situation | Closed route | Evidence level |
| --- | --- | --- |
| Clear current contract | Direct execution; ordinary continuation does not re-run preparation. | Contract review, not a model-behavior test. |
| Missing or conflicting prior meaning | One bounded Discovery returns a source-backed decision; the orchestrator incorporates it before implementation. | Contract review; source completeness needs project-side replay. |
| Ongoing coherence across tasks | Bounded Discovery lead owns design/review, root orchestrator owns dispatch, focused executors own implementation and technical proof. A packet is a checkpoint, not parent completion. | Contract review; no extra role, shared state or scheduler. |
| Lead waits while an executor works | Actual dependency wait stays quiet; an idle lead still recorded as working is visible even when another task is active. | Offline tests exercise actual activity and Guard functions, including CLI input. |
| Consultation or changed dependency | One owner gets actionable work; changed/closed gates route to the orchestrator. Mutual/self waits audit instead of sending endless reminders. | Offline state-transition tests; supplied activity must still be proven by a real adapter. |
| Lost checkpoint, service input or rotation | The durable outbox retains the same receipt; consumption routes the next action without closing the parent or discarding the human question. | Actual parser/routing tests with modeled events, not native delivery or live rotation. |
| Adapter cannot observe the owners | Missing/stale/contradictory observations are LIMITED; old adapters remain compatible but cannot certify leading mode. Use ordinary Discovery until real coverage is demonstrated. | Offline negative tests; native scheduler proof is an adoption gate. |
| Multiple participants or delayed contribution | Each contributes its permitted source-backed delta; one owner integrates a candidate. Relevant participants then retrieve shared meaning and read back the accepted watermark. Missing sources remain explicit; late deltas rebase on current state. | Contract review; no participant synchronization or graph migration performed here. |

The full suite has 42 passing tests, including graph checks, backward compatibility, continuation and whole-lease observation. Those tests establish deterministic parsing and routing only. Semantic coverage, actual tool visibility, native delivery and user value are separate adoption checks. Leading stays conditional on those capabilities rather than advertising unproven automatic protection.

## Evolution Gate

- **Benefit:** preserve accepted intent and working capabilities as changes cross modules, while keeping simple tasks direct and complex work coherent.
- **Evidence and limits:** observed boundary failures motivate the context route; executable regressions cover concrete checker defects and modeled wait/return transitions. Project-wide semantic completeness and fewer real failures are not yet proven.
- **Complexity tradeoff:** replace arbitrary retrieval limits; use one existing workflow for preparation and one optional observation in the existing Guard. Retain three roles, Graph v3, State v2 and direct returns. No new permanent manager, private memory, timer or mandatory research for every task.
- **Verdict:** ship as compatible 1.26 with bounded project-side inventory and capability-gated leading. Defer automated claims about historical completeness or native reliability until independently observed; do not add a general agent hierarchy or graph engine.

## Design References

- [NASA requirements management](https://www.nasa.gov/reference/6-0-crosscutting-technical-management/): bidirectional traceability, parent/source requirements, change impact and independent review. Borrow traceability, not the full formal process.
- [arc42 overview](https://arc42.org/overview/): goals, constraints, context, solution strategy, hierarchical building blocks and decisions.
- [Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions): context, decision, consequences and explicit supersession.
- [GraphRAG DRIFT](https://microsoft.github.io/graphrag/query/drift_search/): broad context can improve local retrieval. Thematic community summaries are not accepted project authority; no new graph engine is required here.
- [OpenAI multi-agent orchestration](https://openai.github.io/openai-agents-python/multi_agent/): distinguish manager-owned coordination from handing off control. A bounded lead does not replace the project orchestrator.
- [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system): delegation has coordination and context costs; multiple agents are not automatically useful for tightly coupled work.
