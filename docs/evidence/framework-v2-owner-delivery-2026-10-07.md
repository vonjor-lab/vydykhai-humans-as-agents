# Scoped Owner Delivery Qualification

Date: 2026-10-07. Status: SCOPED_PASS / NO_RELEASE.
Source manifest: 1.34.1, unmerged 2.0 candidate. No product installation.

## What Changed

The existing host scheduler can invoke an explicitly delegated, finite native
control-disposition handler. This is the existing owner's limited capability,
not another project manager and not a way to wake or replace a desktop chat.
The delegation identifies its owner, authority evidence and next permitted task.
The handler cannot execute repairs, submit repair completion, grant commands or
close findings. Both its native tool allowlist and MCP server enforce this scope.

Its separate private journal claims each source-bound obligation before launch,
retains usage/failed attempts and refuses overlapping re-delivery after restart.
Changing notice ids, their order or batch composition does not authorize a retry.
Paused, unsupported, exhausted and unknown cases cannot silently start another
model. Recovery checks unknown handler runs as well as independent REVIEW runs.
The installed observer reports disposition separately from repair and continuation.

The allowance adapter reads the documented `account/rateLimits/read` RPC without
inference, selects an explicit bucket/window, and retains reset metadata. Missing
or ambiguous data is UNKNOWN. Refresh never refills the model allocation. Pause
and in-flight independent review defer refresh. No credentials are read or copied
by the adapter. The native CLI itself uses an explicitly configured auth home.

## Independent Counterexamples

1. A post-accept response could be persisted during pause or with inadequate repair
   leases and appear applied in notification readback. Thirty-seven new regression
   cases failed before repair. Disposition admission now checks pause, meaningful
   evidence, valid leases, blocking findings and current sources for continuation.
   Notification application independently checks actual state and freshness.
   Source-drift REPAIR remains possible; accepted artifacts/findings remain intact.
   A different fresh reviewer accepted these repairs and reran 102 tests.
2. The disposition-only handler initially received the full owner's repair
   submission tools. A real native client with a scripted provider submitted
   invented repair evidence and changed health to REVIEW_DUE without doing repair.
   The repair tools are now absent and server-denied even if a full-owner native
   profile calls the restricted endpoint. Independent recheck passed; original
   findings, repairIds and host journal remain unchanged after attempted bypass.
3. Main integration review found notice-id-only deduplication could spend again
   on an already attempted verdict. Deduplication now binds obligation id plus
   exact review hash and refuses overlapping batches. Independent regression
   cases cover replacement, reorder, subset, duplicate and mixed batches.

These are scoped findings and repairs, not a claim that all possible bypasses have
been found or that model semantic judgment is universally reliable.

## Observed Limits And Release Gate

The normal operator Codex home was refused as `AUTH_HOME_UNSAFE` before process
launch; no authenticated automatic allowance read was certified. The adapter
requires an explicitly provisioned owner-private, auth-only home. This CLI rejects
`--ignore-user-config` on app-server, and empty MCP config does not remove inherited
entries. We did not weaken the boundary, change the user's permissions or copy
credentials to obtain a green result. Configuration-bearing homes remain refused.
Protocol documentation: [Codex App Server](https://learn.chatgpt.com/docs/app-server).

The new handler does not wake the existing desktop orchestrator, execute its repair
work or deliver a human alert when host intervention is needed. Those cases remain
explicit owned attention, not completed delivery. It is optional and scoped;
activation must never imply general project ownership or full controlled adoption.
The finite journal is not a long-lived storage-capacity solution.

Still required: one frozen held-out semantic preparation/application/acceptance/
retention/continuation cycle; supported existing-project installation and active
service rollback; isolated whole-chain baseline comparison; separate project-side
canary with sanitized evidence and final independent acceptance. No subscription
savings are claimed. The earlier C12.01 failed repair is unchanged and remains
owned; it was not rerun or declared closed by these new tests.
