# Health Activation Qualification

Date: 2026-10-07. Candidate only, NO_RELEASE; public manifest remains 1.34.1.
Only disposable synthetic repositories were used. No live product was inspected,
installed, paused, modified or steered. No permanent schedule remains from testing.

## Implemented And Observed

Initial health is enrolled in the protected journal without inventing a product
acceptance. Interval, source and custody changes are observed outside the manager
conversation. The same existing independent REVIEW, owner disposition and retained
finding history apply. Actual Git refs, worktrees, dirty bytes and staged blob
identity are read; no producer code contents are delivered to a model. Bounded or
unavailable observation is LIMITED, not a clean project or zero branches.

Private activation preserves existing journals, human pauses, unknown effects and
finite allocation across restart. Missing installed journals cannot be recreated
to refill the budget. Reviewer room is separate; protected existing authorization
is referenced without copying secrets or changing operator configuration.

A real disposable macOS launchd SESSION job ran the copied observer without a
manager and retained a receipt. Pause and zero budget launched no model. The job
was unregistered, its absence verified, and its journals preserved. Registration
is not diagnosis, delivered human notification, successful repair or readiness.
LOGIN persistence is implemented but logout/reboot has not been qualified.

## Independent Counterexamples

Independent review found five defects despite the initial green tests:

1. A second pending repair could overwrite the first repair's attempt accounting.
2. Replacing a branch at the same branch count did not trigger new consideration.
3. Dirty-count-only observations missed changed content, including staged blobs.
4. Substring matching could treat a different launchd argument as the owned job.
5. Missing observation dependencies prevented unregistering an owned schedule.

All were reproduced and repaired. A different fresh reviewer returned SCOPED_PASS
after 20 focused passing tests, one skipped native-model test and additional
disposable probes. Removal holds the dispatch lease through unregister so a timer
cannot dispatch a reviewer between identity check and removal. Unknown ownership
is not stolen. Exhaustive timer-race stress and whole-framework correctness were
not claimed.

## Repair Outcome

The same fixture was repaired without changing product code, deleting branches
or erasing the earlier assertion. Current memory now preserves identifier
spelling; the rejected lowercasing assertion remains explicitly historical.
The registry and Git baseline were retained. A separately bounded fresh REVIEW
closed six original findings with source-bound proof and preserved their original
criteria/evidence. One original C12.01 remains OPEN with attempt 1 / FAILED:
the reviewer could see five dirty artifacts but not their identities in the
repository observation, so it could not establish complete local-only custody.

This revealed a real observation limitation. The candidate now supplies bounded
relative dirty paths/statuses, still no file contents. Deterministic tests verify
that metadata, content/index freshness and quiet ordinary commits. No second paid
repair review was launched to obtain a prettier result. The earlier frozen run
does not retroactively qualify this added metadata semantically.

A trusted fixture owner, not another model, consumed the partial result and
recorded CONTINUE only for independent work, with the nonblocking residual in
WAITING under its original owner/checkpoint. Its failed attempt was unchanged;
another repair attempt requires an independently recorded decision. Health state
is SETTLED with owned debt, not all findings closed or whole-project readiness.
No product command, deployment or cleanup was authorized or executed.

## Limits And Next Gate

Complete repair verification, full combined preparation/execution/retention, old-project
adoption and rollback, notification/reconciliation, subscription-reset alignment
and matched whole-chain economics are distinct obligations. A model finding a
problem and its owner storing a plan do not close those obligations.
Unknown leases and exhausted budgets remain visible holds, not automatic retries.
The health-enabled v2 journal rejects legacy readers; schema migration is not
implemented. This evidence does not authorize releasing or installing 2.0.

The local harness is `scripts/qualify-control-health.mjs`; it is maintainer-only,
not included in the staged runtime or automatically run by the test suite.
Raw synthetic receipts and traces are retained outside the source repository.

Final frozen full suite: 575 PASS, zero failures, one platform-inapplicable test
skipped (576 total), with native cases enabled. Manifest validation and diff
whitespace checks pass. An earlier full run overlapped a maintainer documentation
edit and correctly detected a changed adoption-plan identity; that run is retained
as invalidated, not silently counted as a passing qualification. The final run
used stable source files. Full-framework release acceptance remains outstanding.
