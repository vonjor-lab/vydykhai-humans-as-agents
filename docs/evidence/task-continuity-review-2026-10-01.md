# Current Task Continuity: Release Review

Scope: corrective candidate for 1.33.1; live adoption remains unproven by installation. This sanitized compatibility case contains no project identifiers, private task contents or product artifacts. Actual publication status is established by the remote tag and GitHub Release, not this review.

## Failure And Scope

A worker reads a new delegated assignment, compacts within the same native turn and ends by answering a historical human annotation. Its current outcome and Return are unfinished. Repeated same-context reminders recover progress temporarily but do not prevent recurrence. A quiet model-backed heartbeat is also mistaken for model-free monitoring.

The existing continuation rules already reject side answers as task completion. The increment makes that route sensitive to observed current assignment identity and a readback after the latest native restoration boundary. It does not add a role, timer, datastore, semantic judge or a task on every compaction. Data/authenticity collection belongs to the existing project adapter; the checker never reads private conversations or invokes a model.

## Changes And Review

- `evaluateTaskIdentity` compares work, approved revision, checkpoint, latest applicable human event and observed context epoch. It rejects missing/wrong-turn/wrong-owner evidence instead of guessing. An epoch identifies the real observed context boundary, not a clock invented by the caller.
- A mismatch uses the existing manager wake/deferral/incident route. One failed restoration changes the recommendation to a bounded fresh-context review, not an authorized replacement or replay. Fixed artifacts and outcome ownership survive; the old owner must stop before transfer.
- Existing terminal blockers, unavailable outcomes, readiness denials and human waits retain priority. A result for an outdated assignment cannot masquerade as the current result. Matching identity is not semantic acceptance of its content.
- Enrolled observations apply to both next-action and whole-lease evaluation. Contradictory identity fields remain LIMITED even when both views report the same routing verdict; legacy observations remain usable without claiming the new guarantee. The observation key ignores field order/evidence wording and is not an authentication token.
- Event-scoped instructions and the adoption procedure distinguish a native model heartbeat from an external pre-model check. No live scheduler is edited and no new scheduler is installed by this patch.
- Reporting compares model coefficients at fixed tokens separately from workflow cost on comparable accepted outcomes. Unallocated volume/effort/workload changes are not mislabeled as framework savings.

## Offline Replay

`tests/task-continuity.test.mjs` exercises the executable path through the installed CLI exports, not just prose matching:

1. Current assignment and exact post-restoration readback: active work remains quiet.
2. Old work, revision, checkpoint, human event or context epoch: restore current assignment.
3. Correct readback before same-turn compaction followed by an old-question final: restoration, not result reconciliation.
4. Repeated loss after one evidenced failed restoration: fresh-context review; no mutation, restart permission or Candidate deletion.
5. Wrong turn/owner, absent or malformed evidence, duplicate failure receipts: limited observation.
6. Human pause, denied access or unknown outcome: preserve the real gate, not another restoration attempt.
7. Busy manager: defer the wake without consuming it; conflicting whole-lease projection stays limited.
8. Successful restoration and twenty unchanged checks: NOOP, without invocation or timer side effects.

Review caught and corrected four issues before acceptance: readiness denial must precede restoration; turn identity alone cannot invalidate pre-compaction readback within the same turn; identical verdicts do not prove identical observed assignments; adoption requirements must explicitly carry the new check. Schema tests also reject combined JSON keys that resemble two required fields. Shared framework validation enforced existing document size limits; the limits were not raised.

An isolated upgrade test runs the actual published 1.33.0 updater, installs the current kit, checks its own doctor and adoption-plan, and imports the installed classifier. It replays stale readback, one failed restoration, a newer human pause, current result reconciliation and twenty unchanged checks. Repeating the update preserves the plan identity and retained project files. These are simulated observations through real installed code, not an observed native compaction or scheduler proof. Existing joined update/Return regressions remain in the full suite.

## Adoption And Evidence Limits

Offline tests establish deterministic classification and legacy compatibility, not model obedience or hook coverage. This patch cannot intercept arbitrary native final responses, authenticate self-reported readback, stop host compaction or guarantee a fresh worker's reasoning.

Before claiming live protection, the project owner must reuse its existing authorized adapter/worker route to demonstrate: a retained current assignment -> actual compaction -> readback after that boundary -> current next action and Return; a newer human pause remains paused; an unchanged scheduled check creates zero model invocations. If the host cannot expose a required boundary, declare that exact capability LIMITED and retain a bounded approved fallback. An installation receipt or empty heartbeat final cannot substitute. Product work does not wait for universal enforcement proof.

No paid evaluation, product-project mutation, profile switch or additional automation is included. The published 1.33.0 comparison artifacts are not revised to fit this patch.

Final verification on 2026-10-01: all 342 tests passed, with zero failures or skips, including 20 new targeted cases; `node scripts/validate-framework.mjs` and `git diff --check` passed. The full suite includes existing continuation, readiness, Guard, context, installer/update and version-metadata regressions. Runtime comparison coverage is reported separately from legacy activity coverage, so an unenrolled worker cannot gain the new guarantee merely from COVERED activity. Always-loaded core grows from 1,557 to 1,588 whitespace-separated words; the pure helper is 38 lines. These are scope measurements, not token/quota savings.

## Evolution Gate

Benefit: reduce repeated old-task answers and distinguish actual cheap monitoring from silent model use. Evidence: targeted executable negative/continuation tests plus the full existing suite and isolated update replay; live host behavior still requires adoption proof. Complexity: one small pure helper integrated into existing checks and event-specific clarification; no additional runtime loop. Verdict: ship after final validation and publication authorization as a bounded corrective patch, not a claim of guaranteed recovery or measured workflow savings.
