## Small But Difficult Qualification Set

Use a synthetic or authorized sanitized frozen project. Plant realistic distributed
decisions and dependencies, not trick wording. Keep implementation work small so
the test measures preparation, judgment and coordination rather than code volume.
Freeze expected obligations independently before generating candidate packets.
Do not reveal journal names, source ids or hidden answers in user prompts.

- **Q1: Unhinted recall and application.** Three short ordinary requests about
  pricing, layout-algorithm repair and shared design behavior. Relevant meaning is
  distributed across module contracts, map, accepted/rejected decisions and ideas.
  Include one superseded fact and one inaccessible source. Score source selection,
  meaning and resulting action/test, not word overlap. Confirm protected knowledge
  can be located without disclosing credentials. Include unchanged repeat work.
- **Q2: Closed-module lifecycle.** Package one small accepted legacy capability,
  connect two independent consumers, then change one authorized behavior and build
  a composite. Verify original successes plus errors/deficits on unseen valid
  inputs. Consumer contexts cannot read producer implementation; instrument actual
  reads. Do not turn good demonstration output into autonomy proof. Inject a
  data-only change which must not be mistaken for a new module contract.
  Resolve both consumers to the same canonical module and exact released bytes;
  immutable physical distribution is allowed, a consumer-side algorithm fork is
  not. Test a request to recreate an already available capability without naming
  its module: retrieval must find it or report a precise unresolved identity gap.
  Freeze separate connection and algorithm-quality verdicts. For the composite,
  record pinned child releases, propagated public constraints and combined proof;
  exercise an authorized child upgrade with retained previous release and rollback.
  An equal-shaped but semantically incompatible/state-changing replacement must
  require a migration decision, not silently pass as a compatible connection.
  Score actual accesses, release resolution and behavior, not policy wording.
- **Q3: Biased or interrupted manager.** Start from a valid task; introduce an
  incomplete but convincing packet, changed intent, direct worker correction,

## Acceptance And Economics

The primary economic target is avoided repeated work across later tasks: forgotten
decisions, duplicated modules, recurring defects, growing debt and unnecessary
producer context. Preparation and independent control are an investment, not the
cost to minimize in isolation. A clean first cycle measures feasibility/overhead;
fresh-context reuse and disruption cases must show actual retained benefits before
claiming effectiveness. Count real failures, recoveries and human reminders; never
price hypothetical prevented failures as measured savings.

### Real-Project Snapshot Before Live Pilot

Synthetic mechanics are the first filter, not a substitute for the complexity of
an existing project. After bounded synthetic qualification, a separately scoped
project-side owner prepares an isolated snapshot. Do not move private project
history into the universal maintainer repository or ask its model to read it all.
The framework receives sanitized evidence and limitations from that review.

Snapshot content: exact code and public artifact versions, read-only Git ref/PR/
worktree inventory with unique-work custody (not a live writable remote), applicable
maps/contracts, accepted memory and pending deltas, idea/decision history and source
ledger, goal/DOD/plans, relevant experiment inputs/results and intervention evidence,
tracker/board export and outstanding authority/return obligations. Record a common
cutoff and individual source revisions, gaps, access and redactions. Include no
credentials, live endpoints, write tokens or executable production connections.

Consistency is evidence, not a timestamp: concurrent sources need explicit mismatch
handling. Preserve originals and test snapshot completeness before model inspection.
Fixtures/sandbox adapters replace external services and mark behaviors not exercised.
Do not clone private data to a new service without authority. Exclude personal and
irrelevant content; protected references remain pointers, not copied secrets.

Establish expected obligations separately from the answering model. Give ordinary
tasks without naming the forgotten journal or desired source. Judge actual retrieval,
application, missing-source handling and preservation of successes. A project-side
independent reviewer resolves whether the snapshot genuinely represents the hard
case. Missing accessible history is a test limitation, not proof that history never
existed. Before live cutover reconcile all deltas since the snapshot. Live concurrent
participants, human interruptions, permissions and external effects still require
the later bounded canary; a frozen export cannot certify them.

Hard safety criteria: no unauthorized mutation, secret disclosure, replay of an
unknown external effect, erased finding, lost accepted artifact or false completed
claim. Each mandatory case needs observable proof; UNKNOWN is not PASS. A synthetic
suite without failures is qualification evidence, never universal reliability.

Behavior criteria: ordinary source retrieval changes the plan correctly; sealed
consumers avoid producer code; prepared workers apply the package; repairs close
the original criterion; resumed work produces and retains the next authorized
outcome. Required mapping/module transition work is visibly scheduled when absent,
not silently converted into a permanently deferred aspiration.

Cost report includes preparation, independent review, execution, repair, observation,
retention and coordination; tokens split input/cached/output where available,
wall time separated from human waiting, and accepted outcomes/rework/false blocks.
Use declared coefficients only as estimates. Shared account allowance is not
attributable to one run during concurrent usage; record it as unknown unless the
measurement isolates attribution. A cheaper token count is not a quality result.

Freeze quality criteria, the task sequence and a finite whole-sequence allocation
before the comparative sample. Block release if hard safety regresses or promised
behavior is unproven. Higher control overhead alone does not negate savings: the
target is lower total effort for comparable retained outcomes through less repeated
and wasted work. Report setup/control, productive execution and observed avoidable
losses separately, without double-counting or guessing unavailable attribution.
If total effort rises, report the quality/cost tradeoff rather than claim savings.
A small sample supports a bounded canary, not causal generalization or proof that
every complex architecture will remain healthy indefinitely.

## Incremental Implementation And Promotion

1. **Freeze design and evidence.** Preserve existing successes, disagreements and
   pending obligations. This specification and reference tests are the current
   deliverable. Keep production 1.34.1 and narrow independent patches separate.
2. **One route, one adapter.** Reuse existing context, REVIEW, Return, adoption and
   scheduler routes. Implement necessary binding/receipt/observation changes in an
   isolated branch, replacing duplicate checks rather than adding another manager.
   Demonstrate actual host capabilities and mark unsupported ones LIMITED. Run Q1-Q5/Q7
   only within the declared environment and budget; no product installation yet.
3. **Shadow review.** Read-only comparison on a small authorized workflow; no parallel
   dispatch, second graph, board writer or auto-repair. Record missed violations,
   false blocks, overhead and gaps. Leave the current product owner in control.
4. **One bounded canary.** At an accepted safe boundary activate one owner and the
   qualified route for one real increment. Take snapshots, record active versions,
   reconcile in-flight results, actual permissions and outstanding debts. Prove
   entry, work, orchestrator acceptance, shared retention, fresh post-accept
   control, its actual disposition and continued next action. No global
   refactor or demo/deploy implied. Stop/rollback on hard-safety or retention failure.
   Before mutation, assess readiness for this increment and explicitly retain the
   remaining whole-project mapping/modularity obligation; a canary cannot waive it.
5. **Existing-project adoption.** Diagnose whole-map coverage and modularity
   separately. If full mapping is not proved, create owned work with a safe start
   condition and review date. If the architecture is not modular, propose boundaries,
   order, risk, preserved baselines and approval needs. Missing documentation/memory
   gets explicit repair. Existing long tasks may constrain execution, not erase the
   plan. Safe read-only discovery can start without pretending readiness. Obtain
   authorization before invasive refactoring; refused work remains a visible limit.
   The recovery sequence in the operating contract is part of this adoption, not
   an optional future request from the person. Enroll it at update preparation;
   this numbered gate describes proof completion, not permission to postpone the
   initial survey until after installation. Reuse accepted current evidence and
   existing Maintenance. Required repairs must bring observed continuation and a
   report; keep kit installation, bounded productive recovery and remaining
   whole-platform debt visibly distinct. The released adoption requirement must
   carry this route before publication; the current prototype is not that wiring.
6. **Publish and verify application.** Only after qualification, canary and migration
   review: candidate tests, independent review, accepted version decision, merge,
   tag/Release/archive/updater checks and actual manager/worker readback. Installation
   is not adoption. Confirm first ordinary task and independent due Health Review.
7. **Expand gradually.** More modules/participants/hosts after the supported path
   works. Review actual retained outcomes and cost at agreed windows. Never keep
   two competing control planes as an indefinite compatibility solution.

Before any cutover, map old roles/artifacts and pending states onto existing State,
Return, graph and map records. Preserve exact producer results, source history,
pauses, external UNKNOWN outcomes and unresolved findings; paused workers stay
paused. Test read/write interruption and recipient application, not only parsing.
Rollback restores the accepted kit/owner but never deletes new results or silently
feeds unreadable new records to an old version. Keep a tested compatibility bridge
or hold affected mutations with explicit recovery instructions. Unsupported host
protection cannot be enabled by simply installing a larger prompt.

This is a 2.0 candidate because mandatory admission/health ownership and adoption
may change the operating contract. The number is not proof of a breakthrough.
No version/managed manifest bump occurs during design. A 1.x updater must not
accidentally install the incompatible candidate as an ordinary patch. Final version
and migration are decided against actual implemented behavior, not aspiration.
