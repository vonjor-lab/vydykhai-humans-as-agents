## Vydykhai Managed Rules

- Read `docs/FRAMEWORK.md` for the current operating core.
- Read the atomic Project State control snapshot before checking the framework and reconcile its Pending Return Inbox before trusting native messages or chat. Run `doctor` for kit integrity and `control-check` on current Project State/graph exports before activation, schema cutover, or rotation. After a framework merge, activation additionally requires the active orchestrator's own clean cwd at the accepted HEAD, live/offline doctor for the target installed/source versions and schemas, reread updated core, and agreement with title and Project State. A maintenance or verification worktree proves only the Candidate; mismatch keeps the prior version active and routes `ACTUAL_CONTEXT_COHERENCE` repair or confirmed rotation. Check upstream on first active use after 24 hours; stay silent when current, otherwise report every skipped release and one safe update window.
- Keep one active Framework Orchestrator per participant and stream. It owns one DOD Control Line, Execution Leases, return routing, memory integration, sequence, and next-best-action; it never performs project work. A role-`EXECUTION` task implements and proves one accepted increment.
- `ORCHESTRATOR_WORK` may use bounded internal advisory agents on the maximum profile when their only durable result is a control decision. Give each `Control decision / Available sources / Expected orchestration output / Route to focused context when`; require `CONTROL_ONLY` or `ROUTE_TO_FOCUSED_CONTEXT` in the same control cycle. Their notes are disposable, have no Execution Lease or task Return Sync, and never count as project evidence.
- Keep one project-owned Project Guard outside the active orchestrator context. It runs deterministic `guard-check` from control events and an independent schedule; one runner-owned incident ledger records delivery, acceptance, and repair attempts. Incident identity is the semantic condition set, not snapshot hash. Routine State revisions and non-authoritative view drift create no model/message trace or Graph update. It wakes durable waiting work once and starts a fresh maximum-profile evaluator only for a genuine anomaly or a proved unresolved wake. `REPAIR` permits one transactional repair and deterministic readback; PASS closes model-free, while the same remaining condition becomes `CONTROL_DEGRADED` and stops retries. Adapter implementation and smoke belong to a visible focused service task; the orchestrator only coordinates and accepts its receipt. Preserve one plain-language `Pending Human Action` and the existing productive Next-Best-Action across Guard, repair, and rotation, then resume or explicitly supersede each. Follow `docs/workflows/production-continuation.md`: act on ready management work before releasing the turn; require observable execution or a real wait, not maintenance dispatch alone. Fresh activity guards against false stalls; missing visibility is `LIMITED`, never permission to duplicate work.
- Keep three context layers isolated: canonical framework maintenance evolves universal rules and releases; a project orchestrator coordinates one project; focused task, discovery, lab, and maintenance contexts perform all project work. Task returns end at the project orchestrator. Project adoption of a framework release is owned locally; do not ask upstream maintenance to install it or operate the orchestrator. Never route Project State, task links or status, people, backlog, private evidence, or project next-best-action upstream. Framework feedback requires a separate explicit sanitized compatibility packet.
- Register active orchestrator context links, installed framework versions, latest packets, and active tasks in Project State.
- Keep project-goal contexts `<work-id> [<track>] [<mode>] — <short outcome>`, with the owning Issue or stable tracker key first and never a PR number; normal execution omits mode. Only service work that maintains the coordination system instead of advancing a project goal puts a concise unique service id first, such as framework version, rotation generation, or Guard incident, and never reuses the Project State issue as work id. Name project control contexts `[ORCHESTRATOR] <project> — Vydykhai <version>` and retired predecessors `[RETIRED][ORCHESTRATOR] <project> — Vydykhai <version>`. Human-facing plans use the same meaningful references, and PRs render as `PR #<pr> → <canonical work reference>`; mutable status stays in tracker/native state.
- Route the latest available flagship by role: `ORCHESTRATOR` uses maximum available reasoning, `DISCOVERY` uses deep bounded reasoning, and `EXECUTION` uses efficient bounded reasoning. Map to `Ultra / XHigh / Low` when those labels exist. Record all mappings, check date/source, and fallback in Project State; recheck at setup, update, orchestrator rotation, model failure/deprecation, and at least weekly Health Review.
- Apply source precedence: latest explicit human decision; approved compass/brief/DOD/delta; current issue/PR/verified repo state; agent plan; inference. Before patching a running task, read its events newer than the last Return Sync and reconcile newer human direction.
- Apply product and coordination guardrails in the orchestrator. A task applies local safety and contract boundaries; it detects a wider boundary and sends `CONSULT`, while the orchestrator decides the project response. A human may explicitly override a recommendation with recorded limits and a re-entry condition.
- Require one shared writable Git-backed repo and durable tracker; GitHub Repo + Issues/Projects/PRs is the recommended default. Coordination inputs may be direct to relevant orchestrators or use one named intake owner and approved traceable delta. Record access in the Shared Sync Contract, mark gaps `SYNC_LIMITED`, and never claim complete alignment for affected work.
- Before first dispatch require a current evidence-backed Project Activation Receipt. `doctor` proves only kit integrity; `$project-launch` proves home/kit, shared sync, participant self-readiness, inputs, first-DOD operations, course, external Project Guard, and control loop as `PROJECT_READY`, `PROJECT_READY_WITH_LIMITS`, `NEEDS_DECISION`, or `BLOCKED_BY_ACCESS`. One machine cannot certify another, and missing participants block only overlap.
- Protect the nearest DOD from optional growth. Project State v2 holds current control; Project Memory Graph v3 holds atomic reusable meaning, Pending Memory Events, and fresh `CURRENT / NEXT / PRIOR_MISS` probes, and advances only for a semantic memory delta. Preserve every “remember/revisit” commitment and every deliberate detour with its meaning, source, aliases, owner, target DOD/lease, return condition, review-by, and human gate. At each cold path derive a Touch Set and give the task complete applicable `Because / Apply / Avoid / Verify / Source` items or raise `MEMORY_COVERAGE_GAP`. Test a memory candidate first with 3-4 ordinary unhinted real-task queries; any miss stops broad evaluation, then receives only targeted regression before atomic shadow integration and human-confirmed cutover. A correction triggers miss classification, smallest graph repair, ordinary-language replay, and affected-work analysis. Follow `docs/workflows/context-route.md`: preserve the complete relevant goal-to-evidence chain and source qualifications; structural or synthetic PASS is not semantic coverage.
- Use `$project-launch` to activate or reconnect a project.
- Use `$start-work` to shape a large or changed topic into a brief and task map.
- Use `$daily-alignment` only in an orchestrator when a meaningful meeting or external event materially changes another participant's safe next action; never use it for task-local failure, routine progress, urgency, or ordinary continue.
- Use `$accept-work` inside the task context before claiming completion.
- Before dispatch, re-brief, or material resume of stale/paused work, classify scope freshness as `UNCHANGED`, `PATCH_REQUIRED`, or `REBRIEF_REQUIRED`; seven days is the default re-read signal, not an automatic scope change. An ordinary continue inside a current active contract is a hot path: read the newest relevant event and do not rerun alignment, memory, freshness, or dashboard rebuild.
- Before unexpected task growth, run Expansion Check and route `CONTINUE`, `REBRIEF`, `LAB`, or bounded `MAINTENANCE`. Treat counts as signals, not verdicts; containment does not close recurring debt without source removal or explicit deferral and representative-flow proof.
- Before dispatch classify the work as `ORCHESTRATOR_WORK`, `DISCOVERY`, `EXECUTION`, or `STALE_OR_REBRIEF`. Implementation tasks receive only a Low-ready role-`EXECUTION` contract: one outcome and first action, no unresolved solution decision, explicit boundaries, objective acceptance, current inputs/access, and narrow consult triggers, plus the nearest DOD, owner, freshness/Baseline, Memory Brief, safety, burn, and verification. Keep Project State, raw Touch Set, unrelated transcripts, full memory, task map, and orchestration deliberation outside the task. A re-brief maps `Preserved / Replaced / Added / Remaining` progress.
- Classify by the owned result, not topic, read-only status, or use of subagents. A new diagnosis, solution, runtime/data fact, experiment, test, Candidate, acceptance proof, side effect, independently useful artifact, or work that outlives the control cycle belongs to a focused context. Material project claims require a human decision, durable source, or focused-context receipt; otherwise raise `UNOWNED_PROJECT_WORK`.
- Use `context-route.md` to choose direct execution, bounded context-recovery `DISCOVERY`, or Discovery with a bounded lead for ongoing cross-task coherence. Explain why and the next visible result; no new permanent role or scheduler. The lead owns design/review, not dispatch or implementation; packets are checkpoints until its parent is accepted or explicitly deferred. Require whole-lease activity/wait coverage before leading mode; otherwise use bounded Discovery. The orchestrator incorporates its Decision Packet before creating execution work.
- Use Lab Mode only when isolation reduces cost or risk; require a decision, Accepted Baseline, one main variable, human-verifiable proof, stop/burn limit, production transfer, and risk-based real-flow verification.
- Use Peer Compass Review when owners overlap on a flow, surface, contract, PR, or DOD row.
- Do not invent another participant's uncommitted state. Missing participants block only overlapping work.
- Publish Project State through `render one complete authoritative record -> validate and hash -> one guarded write -> exact readback -> hash and validation`; preserve and restore the last accepted body on mismatch. Current facts live once in Control Snapshot, Current DOD, Execution Leases, Pending Return Inbox, Detours And Recall, or Next-Best-Action. Activation evidence is immutable; legacy Active Work, decision, safe-continuation, tracker, and graph summaries are disposable projections. Regenerate their drift without a model or control event. A partial or failed write never becomes current truth, and current state never appears after an end marker.
- Before launch record one `PREPARED` Execution Lease with work identity, owner/context, exact base, profile, DOD contribution, review-by, durable outbox, wakeup route, and receipt id. Block duplicates while disposition is unresolved. Move to `STARTED` only after the first safe observable action in the launch/resume turn; this is proof of start, not a new pause or approval. One plan-only repair is allowed; repetition is `EXECUTION_STALLED` and routes replacement or re-brief from durable evidence.
- After the launch receipt, release the orchestrator instead of polling or waiting while valid work runs. The task owns local implementation planning, debugging, corrective fixes, tests, and exact-current-code evidence. It resolves ordinary failures autonomously inside scope/burn and does not run project-launch, start-work, daily-alignment, or framework-orchestrator. At an undeclared scope/authority/safety/shared-contract boundary, stale upstream state, unresolved solution choice, impossible DOD, or repeated no-progress, pause only that boundary and send `CONSULT`; the orchestrator chooses patch, re-brief/split, Discovery, or stop. Never climb reasoning levels mechanically.
- At a named checkpoint, blocker, readiness result, or terminal result, the task writes the marked Return Sync to the durable outbox before attempting the same id as a native wakeup. An Action Receipt never substitutes for Return Sync, and an empty native task/thread read never disproves the durable result. The orchestrator reconciles `WRITTEN / SENT / RECEIVED / CONSUMED / ROUTED` and appends the paired marked Return Route receipt; Project Guard compares those real records independently on write events and timer, wakes once, and stays silent after valid routing. Adapter acceptance proves a real event route plus a scheduled `NOOP` with no queue or model call; malformed or mismatched routing audits. Native loss never requires human polling or recreating work.
- A command, prompt, plan, or send attempt is not a completed transition. Use `PASS / MISMATCH / UNVERIFIED / OUTCOME_UNKNOWN`. The orchestrator owns launch/resume, Return Sync, and memory-reflection/detour receipts; acting context owns protected access; task owns acceptance/live and side-effect receipts. Only `PASS` closes. Routine control transitions are deterministic; Governor authority is bound to one semantic anomaly and never to every later State revision. Uncertain external outcome freezes replay until exact reconciliation.
- Keep one Success Line per accepted increment: one owning execution context and canonical Candidate. Build successors from the Accepted Baseline plus applicable Memory Brief and rejected-candidate lessons; let the orchestrator sequence later increments instead of stretching one task across the product route.
- Product capability acceptance requires the promised user/operator loop, not only backend state, UI shell, route, test, lab proof, or an enabler without its named continuation. Match human checkpoints to the judgment that person owns; require recipient access to the exact shared artifact/revision and an agreed receipt check. For runnable data-backed work, prove the exact environment, schema/migration revision, reproducible safe test-data source, recipient access, and representative scenario; missing required data is `BLOCKED`, not failed product evidence. Classify material deltas as `Inherited`, `Deliberately changed`, or `Unexpectedly changed`; unexplained unexpected change is `NEEDS_FIXES`.
- Verify the risks changed by the Candidate. Smoke runtime/integration/state work on the exact branch, worktree, commit, frontend, backend, and browser target being accepted; avoid a paid setup path when an equivalent controlled entry is valid and that path did not change. For zero-spend/no-mutation work, disable the dangerous capability when practical, prove counters before/after, and disclose any breach permanently.
- Run `$accept-work`, corrective fixes, exact-current-code smoke, human checkpoint, and manual merge in the owning task context. Classify each executable Memory Brief item as applied/missed/contradicted/not exercised. The orchestrator consumes the verdict without repeating acceptance, turns misses into regression scenarios, integrates reusable candidates, then updates affected work, DOD burn, parent closure, alignment, tracker projection, and next-best-action.
- Use one monitor for one named gate; while unchanged create no message, no-op trace, or model wake-up, do not let it expand scope or spend money, and delete it at terminal state.
- During Health Review run one `Work Hygiene Check` over every live task, PR, branch, context, worktree, runtime, and monitor: require owner, current goal/DOD relation, state, and exit or re-entry trigger; classify `ACTIVE / WAITING / FINISH / SALVAGE / RETIRE`. Read shared artifacts from shared metadata and route local-only inspection to each owner's focused maintenance task; one machine cannot attest the team. Age is a review signal, not deletion authority or a fixed branch limit. The orchestrator classifies and routes, recording only the date and unresolved exceptions in Project State; owning or focused tasks inspect and clean. Preserve evidence and unique work, salvage useful stale work onto the current Accepted Baseline, and keep artifact inventory out of semantic memory.
- Rotate only after Governor identifies an unrepaired hard signal and the human confirms cutover; compaction alone triggers review. Candidate independently reconstructs DOD Control Line, unresolved leases, Pending Return Inbox, detours/recall, and current/upcoming/prior-miss briefs from durable evidence. After confirmation retarget every unresolved lease and durable/native return, reconcile the inbox, switch the active pointer, and retire the previous context visibly. Keep unaffected execution running and old context accessible.
- Never put secret values in shared memory. A protected `POINTER` is usable only with owner, protected reference, environment/scope, allowed non-destructive route, last safe check time/result/source, and expiry or re-entry condition. Missing fields make only the affected action `MEMORY_COVERAGE_GAP / BLOCKED` until the pointer is repaired from durable evidence and rechecked; do not silently substitute history search, ask for the secret again, or mutate live state.
- Preserve `docs/VYDYKHAI_NOTICE.md`, creator/license metadata, and the required notice in framework-managed copies. They cover the framework kit, not project-specific work.
- Keep project-specific rules outside this managed block.
