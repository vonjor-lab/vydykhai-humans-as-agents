This is the factual locator within [Context Route](context-route.md), not another memory store, role or authorization mechanism. Start from the ordinary request, not a manually chosen memory-node list:

```sh

```

When the accepted task or module boundary already supplies exact anchor IDs from the graph's Anchor Index, pass them as authoritative roots alongside the ordinary request:

Use `--scope` once with one or more comma-separated, case-sensitive `ENT-...` IDs and no spaces (API: `deriveMemoryRoute(content, request, {scope: ["ENT-MODULE", "ENT-CONTRACT"]})`). ## Operational Recall

Before asking the human to repeat an access decision, recover the known route, authority source, safe pointer and applicable restrictions through preparation. An available but unread source is not a missing decision. If the graph omitted it, use existing pending events/Memory Miss repair and return a source-backed delta to the owner; do not add another store or copy protected values. Check current session/resource readiness only through an already authorized non-destructive route. If that cannot resolve the gap, request the specific missing human action, not a new account or repetition of settled instructions. Keep cleanup authority and scope separate: access does not authorize deletion, credential reset, changed roles, or reuse of expired one-time permissions. Independent preparation review checks the source-to-packet application, not merely the presence of a pointer. Shared integration and subsequent ordinary retrieval are required before a missing-memory finding is closed.

## Working Selection And Context Pivot

Distill into existing records: the integration owner refines current reusable meaning at its existing anchor or explicitly supersedes it, rather than appending paraphrases. An unchanged meaning needs no new record.

Keep parked references with a reason, not full bodies. Replacing the material selection does not drop applicable meaning; a locator cannot certify completeness.

## Memory Understanding Escalation

The first human hint that "we discussed this" triggers existing Memory Reflection, not a second reminder requirement. Treat it as evidence of a possible miss, not proof of a particular historical decision or new authority. A contradiction, missing prerequisite, unexpected consumer or repeated failed assumption also triggers reflection before the affected correction. Record the hint, affected question, anchors and source watermark in the existing checkpoint. Distinguish ABSENT, RETRIEVAL_MISS, APPLICATION_MISS and VERIFICATION_MISS; also label unread, unavailable and conflicting evidence. Pause only decisions depending on the missing meaning; independent work continues. First trace the hinted subject through purpose, decisions and their reasons, alternatives, constraints, prerequisites, consumers and supersession to original source ranges. Then expand only adjacent clusters implicated by a discovered gap or contradiction. Check all applicable relations of that causal boundary, not every node in the project. Public contracts remain the boundary for consumers; never retrieve secret values. Recover a source-backed Before / Now / Why / scope and the smallest changed action. If an authorized bounded pass cannot establish meaning, return the exact unresolved source or decision and owner; do not loop searches or ask the human to retell accessible history. Ask only for unavailable evidence or a genuinely unresolved decision. If the same miss recurs after a claimed repair, reopen that incident and inspect its source -> graph -> retrieval -> application -> verification chain. Use existing owner-routed Discovery/REVIEW for an independent interpretation when needed; the repairer cannot accept their own repair. Higher effort requires a named reasoning gap, not merely more files. Attempts and costs do not reset; no new consultant role or polling loop. Repair the failed link, alias, scope, supersession or application rule in a side-by-side delta through the existing integration owner. Do not add duplicate reminders or a new graph node when the graph was already correct. Preserve original evidence, uncertainty, negative findings, authority and pending questions. A hint does not authorize changing an accepted decision. Close only after stored readback, independent source-based checking of the affected meaning, and ordinary unhinted retrieval plus correct application of that meaning. Exercise one natural paraphrase or adjacent consumer where applicable; retain unrelated passed evidence instead of rerunning the suite. Written repair alone is not closure; until integration/application is observed, keep the gap owned and open. Routine local repair uses existing publication authority; full graph migration and orchestrator rotation retain their human-confirmed cutover. No whole-history inventory is required for a localized miss. Broader reconstruction needs evidenced wider coverage failure. This is event-driven memory health within existing Health Review, not a promise of perfect recall.

Record a retained/added/parked delta in the same packet. Parking does not discharge an obligation: retain its reason, owner and return trigger, then surface it when applicable, not as an unchanged reminder. Preserve applicable constraints, negative findings, human questions, pauses, authority, unresolved effects and independent review requirements unless source-backed evidence resolves applicability. Keep protected-pointer metadata, never secret values. Repair missing links through existing shared integration.

A short note or change of focus does not physically reduce host context. At an authorized safe boundary use the [existing context choice and readback](context-routing.md#execution-context-at-a-safe-boundary), retaining effects, pending questions, spend and reviewer identity. Orchestrator rotation has its own migration approval. Measure observed input and comparable whole-task cost before claiming savings. Repair retrieval before escalating capability; use task-proven preparation models and retain independent source selection. No background polling or automatic dispatch.
