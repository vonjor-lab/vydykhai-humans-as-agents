# Read-Only Memory Recall

This is the factual locator within [Context Route](context-route.md), not another
memory store, role or authorization mechanism. Start from the ordinary request,
not a manually chosen memory-node list:

```sh
node scripts/vydykhai.mjs memory-recall --graph <graph-or-storage-manifest> --request "<ordinary request>"
```

The entry validates the existing Graph v4 representation, matches declared names
and aliases, follows purpose upward and projects public dependencies and consumers.
It retains attached current decisions, commitments and linked prerequisites without
ranking away low-match obligations. It does not read producer implementations or
change the graph. Multipart storage uses the same logical graph, not another store.
Selected `POINTER` items retain `protectedPointer`: the existing six-field safe
reference, owner, scope, permitted check, historical observation and re-entry rule.
Recall does not open the referenced resource or prove current access. An old check
is neither current readiness nor evidence of expiry. Missing records remain gaps;
the locator cannot recover a decision that was never integrated into the graph.
An unrelated pending event does not block read-only inspection; an applicable
pending event, provisional/conflicting meaning or unavailable source remains a gap.
The normal graph readiness validator still refuses pending integration.

`About` links also locate related evidence; they do not recursively select every
other subject's complete history. Explicit `requires` and `constrains` still close
obligations. Unselected records reached only through those associations remain
visible as `navigationCandidates` and require applicability review, not a silent
PASS. Their source/status, relevant contracts and pending coverage are retained.
Explicit constraints on associated anchors also remain obligations. Their outgoing
purpose/dependency routes retain navigation and an applicability gap, not full sibling text.
The preparer resolves that question from sources; this does not authorize deleting
an inconvenient constraint or replacing an oversized required meaning with an id.
Contract anchors are valid recall roots, not automatically approved execution units.

Repair a known historical gap in the existing v4 graph beside the accepted version,
not in a second active JSON memory or custom reader. Retain original records and
source coordinates, add actual user-language aliases to the appropriate artifact
or entity, and preserve decisions, reasons, alternatives and exceptions in canonical
fields. A historical artifact must not masquerade as the current module. Where
current applicability or supersession is unresolved, keep reconstructed lessons
`PROVISIONAL` and coverage `PARTIAL`; historical human acceptance is not a new grant.
Old probe rows remain old evidence, not acceptance of a changed graph. Verify the
same canonical meaning through CLI preparation and the registered-source reader,
and independently read original evidence through `list_sources`/`read_source`.
The preliminary reconstruction format can remain archival evidence but is not an
additional installed memory format. Publication and actual participant application
still belong to the existing owned adoption checkpoint.

`RECALL_CANDIDATE` means a candidate navigation packet, never complete recall or
execution admission (`semanticTruth: NOT_VERIFIED`, `admission: NOT_GRANTED`).
Unknown phrasing, ambiguous aliases and broad outcomes go to bounded Discovery;
the lexical locator does not infer arbitrary synonyms or decide applicability.
Read public contracts, the relevant map and primary-source evidence through the
existing preparation route. A fresh independent evaluator selects against those
sources, not only against this packet, before required readiness can be accepted.
Missing graph relations can hide an obligation even when structural validation
passes. Graph hashes identify provenance, not a global authorization dependency.
Graph prose is not automatically sanitized: preparation checks that selected
meaning is consumer-safe, and does not load implementation snippets just because
they were written into a memory node. This command does not replace that check.

The projection has a transport budget, not a logical-memory/node limit: an
oversized result requires task decomposition, never silent loss of obligations.
The file adapter currently reassembles the whole graph locally; it does not claim
indexed storage-scale retrieval or protected-source access. Exit 0 means candidate
projection returned, 1 means invalid/unreadable input, 2 means Discovery is needed.
After acceptance and actual integration, the next ordinary task repeats retrieval
at the new watermark; saved but unintegrated deltas cannot count as remembered.

The existing registered-source MCP adapter can expose `recall_memory({id,request})`
to an explicitly enabled factual preparation profile. It reads a registered inline
Graph v4 or the existing storage manifest whose every whole part has exactly one
registered path. It verifies part bytes, logical graph hash and index locally;
the packet returns source/part identities, not archival parts or the full index.
Unregistered, ambiguous, marker-selected or changed parts refuse the whole recall.
Each whole source remains capped at 128 KiB, acquired manifest plus parts at 2 MiB
and the returned packet at 64 KiB. Oversized invalid-graph diagnostics stay BLOCKED
with their count/hash/byte length, not a raw dump or silently accepted subset.
A registered unique marker section may live inside the existing 2 MiB artifact
envelope; markerless files still cap at 128 KiB. It cannot follow arbitrary paths.
This is not indexed or unlimited storage. Default independent-review profiles
keep only `list_sources` and `read_source`, so reviewers independently select from
primary evidence rather than treating the locator as a completeness certificate.
Enabling this tool neither authorizes execution nor proves installed adoption.

On update, the existing prepared-work adoption owner reviews the graph/map/source
route and registered selectors/whole-part bindings, repairs demonstrated gaps or
records source-backed NO_CHANGE. Retain actual acquired identities in the existing
preparation/source binding; a manifest-only hash cannot certify changed part bytes.
Prove stored readback and ordinary next-task application after shared
integration. Oversize or unavailable storage stays a visible owned pending gap;
this bounded selector change does not authorize a whole-memory rebuild.

Physical limits remain explicit. The local control journal caps each complete
revision at 8 MiB and verifies its whole history on read; it is not indexed or
unbounded storage. Capacity refusal cannot turn an unwritten delta into integrated
memory or an uncertain reservation into completion. Retain the old bytes and
pending owner/checkpoint; resolve capacity before the dependent action. Graph
packing preserves logical bytes but still reassembles the graph locally. A short
projection from a large graph proves bounded worker context, not constant-time I/O
or arbitrary project scale. Do not delete history or silently shard authority to
work around these limits.

## Operational Recall

Before asking the human to repeat an access decision, recover the known route,
authority source, safe pointer and applicable restrictions through preparation.
An available but unread source is not a missing decision. If the graph omitted
it, use existing pending events/Memory Miss repair and return a source-backed
delta to the owner; do not add another store or copy protected values.
Check current session/resource readiness only through an already authorized
non-destructive route. If that cannot resolve the gap, request the specific
missing human action, not a new account or repetition of settled instructions.
Keep cleanup authority and scope separate: access does not authorize deletion,
credential reset, changed roles, or reuse of expired one-time permissions.
Independent preparation review checks the source-to-packet application, not
merely the presence of a pointer. Shared integration and subsequent ordinary
retrieval are required before a missing-memory finding is closed.

## Working Selection And Context Pivot

Durable memory is retained; only the working selection changes. Use the existing preparation packet/lease, not another graph, role or controller. Record the current
question, anchors and source watermark; applicable obligations and exact source references; unresolved gaps; and the next action. Keep parked references with a
reason, not their full bodies. A locator cannot certify that all meaning is known.

Keep two views in this same packet: semantic meaning (goal, rationale, constraints, rejected approaches and commitments), and material selection (contracts, files, tests and evidence). Link meaning to artifacts and checks; retain applicable meaning when replacing material. Neither view is a second memory store.

## Memory Understanding Escalation

The first human hint that "we discussed this" triggers existing Memory Reflection, not a second reminder requirement. Treat it as evidence of a possible miss, not proof of a particular historical decision or new authority. A contradiction, missing prerequisite, unexpected consumer or repeated failed assumption also triggers reflection before the affected correction.
Record the hint, affected question, anchors and source watermark in the existing checkpoint. Distinguish ABSENT, RETRIEVAL_MISS, APPLICATION_MISS and VERIFICATION_MISS; also label unread, unavailable and conflicting evidence. Pause only decisions depending on the missing meaning; independent work continues.
First trace the hinted subject through purpose, decisions and their reasons, alternatives, constraints, prerequisites, consumers and supersession to original source ranges. Then expand only adjacent clusters implicated by a discovered gap or contradiction. Check all applicable relations of that causal boundary, not every node in the project. Public contracts remain the boundary for consumers; never retrieve secret values.
Recover a source-backed Before / Now / Why / scope and the smallest changed action. If an authorized bounded pass cannot establish meaning, return the exact unresolved source or decision and owner; do not loop searches or ask the human to retell accessible history. Ask only for unavailable evidence or a genuinely unresolved decision.
If the same miss recurs after a claimed repair, reopen that incident and inspect its source -> graph -> retrieval -> application -> verification chain. Use existing owner-routed Discovery/REVIEW for an independent interpretation when needed; the repairer cannot accept their own repair. Higher effort requires a named reasoning gap, not merely more files. Attempts and costs do not reset; no new consultant role or polling loop.
Repair the failed link, alias, scope, supersession or application rule in a side-by-side delta through the existing integration owner. Do not add duplicate reminders or a new graph node when the graph was already correct. Preserve original evidence, uncertainty, negative findings, authority and pending questions. A hint does not authorize changing an accepted decision.
Close only after stored readback, independent source-based checking of the affected meaning, and ordinary unhinted retrieval plus correct application of that meaning. Exercise one natural paraphrase or adjacent consumer where applicable; retain unrelated passed evidence instead of rerunning the suite. Written repair alone is not closure; until integration/application is observed, keep the gap owned and open.
Routine local repair uses existing publication authority; full graph migration and orchestrator rotation retain their human-confirmed cutover. No whole-history inventory is required for a localized miss. Broader reconstruction needs evidenced wider coverage failure. This is event-driven memory health within existing Health Review, not a promise of perfect recall.

Record a retained/added/parked delta in that same packet. Parking does not delete memory, supersede a decision or discharge an obligation. Applicable constraints, negative findings, human questions, authority, unresolved effects and independent review requirements remain active; exclude them only with source-backed resolved applicability. Preserve protected-pointer metadata, never secret values. Repair a missing durable link through the existing owner and shared integration route.

Changing focus cannot remove prior messages from a host's input. At an authorized safe boundary use supported compaction, or an authorized fresh executor with the
same logical task and saved checkpoint; never replay an uncertain action or leave
competing executors. Retain effects, pending questions, spend and reviewer identity.
The recipient retrieves the current required sources and reads back the next action
before executing. Orchestrator rotation retains its separate migration approval.
Compare actual input after the pivot using existing context measurement; a smaller packet alone proves no saving. Repair retrieval before escalating capability;
use only task-proven preparation models and retain independent source selection.
No background model polling or new automatic dispatch is introduced by this rule.
