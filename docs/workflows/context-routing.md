# Owner-Controlled Context Routing

When comparing operating versions, separate model-rate substitution from workflow efficiency. Reprice the same observed input/cached/output tokens using dated official coefficients to estimate the model-only effect; do not treat that scenario as actual subscription attribution. Compare preparation, execution, review, recovery and coordination on equivalent accepted outcomes for the workflow effect. If workload, effort or concurrency changed, label the remaining token-volume/composition difference unallocated, not framework savings. Account-wide limit snapshots cannot identify a task's share during parallel work. A cheaper model can conceal repeated work; record avoidable stops, human corrections and retained outcomes alongside tokens. Reuse existing receipts, not an extra periodic measurement agent.

This implements the preparation branch of [Module Delivery](module-delivery.md) through [Context Preparation](context-preparation.md), not another management hierarchy. Context readiness is checked at every start and material information gap. Reuse a sufficient current packet; do not repeat an exhaustive search.

## Responsibilities
### Execution Context At A Safe Boundary

At every dispatch or material resume, including focused Discovery and Lab, the owner uses the existing startup/lease to choose sufficient context and model for the remaining accepted outcome. Reuse sufficient preparation and its delivery-boundary trace; do not create another packet or approval to make this decision. Record the choice before deriving the native call parameters, not retrospectively from what the host happened to inherit:

- **Context:** selected source-backed meaning, public contracts, artifacts and exact gaps by default; retain originals outside the active input. Reuse a suitable unfinished owner when it avoids more transfer/rework than it creates. Full-history inheritance needs a scoped reason; same topic or familiarity alone is insufficient. Completion of computation may leave storage/presentation repair: carry its relevant evidence, not the whole implementation history.
- **Profile:** accepted project-local task-class model/effort and its evidence, or a named capability, availability or human-choice exception. An exception has a return condition, is reconsidered on material resume and expires at task completion; successors do not inherit it. The owner decides within accepted authority; exceeding that authority needs a human decision, not repeated technical permission. Repeated exceptions trigger the existing Health Review rather than perpetual renewal.
- **Host path:** whether the permitted route can set context inheritance and model/effort. Supply supported parameters explicitly from this decision. Unsupported selection is LIMITED/inherited before launch, never a claimed switch; use a sufficient authorized fallback or retain the exact gap. An omitted model setting is not evidence of economical selection. No host limitation relaxes safety, scope, budget or required review.

Bind actual readback to the current assignment revision, worker and launch/resume turn in the existing lease. Record requested versus observed model/effort and context route separately; observed evidence takes precedence without erasing the earlier decision or mismatch. At the first available response, record first-request input including host/history overhead (or UNKNOWN); later/max input is a separate measure, never a replacement for the first. Use exposed telemetry or `context-prepare measure`, not packet bytes or quota percentages. Missing/stale evidence cannot establish application; no extra model call is needed for readback. Native calls that bypass this workflow remain outside enforcement: a consistent record is not a host fence.

When `SAFE_BOUNDARY_REFRAME_DUE` or evidenced repeated broad rereading occurs, record one boundary action in the existing lease/checkpoint. Finish the current atomic operation first; retain source originals, latest human decisions, secrets references, accepted/candidate artifacts, failures, accrued cost, pending receipts and uncertain effects. Use supported compaction or an authorized fresh physical executor with that selected packet, not a fork carrying the entire transcript. Transfer the same logical task and sole execution lease only after the previous owner is quiescent and effects are reconciled. Require current assignment/source readback before its next action. Never run two owners or replay a completed action. Do not rotate the project orchestrator under this executor rule.

Judge any correction by expected cost of the remaining outcome, including transfer and rework, not by the desire to clean up a mismatch. Lack of an in-place model switch does not justify indefinite expensive reuse: consider an authorized selected-context transfer; if unsuitable, retain the reason and next natural boundary. Do not relaunch solely to improve a metric; first-input cost is already spent. No arbitrary universal token cap: derive the budget from sufficient context and host limits. A new session does not reset cost or authority. Never switch an in-flight operation, alter review routing or relax acceptance to save tokens. Independent acceptance retains its distinct context and accepted profile; an already-required review can inspect this evidence without adding a new review stage.

During execution, combine related source reads and local checks into bounded tool operations when the host supports it. Return selected results and retain originals on disk; never batch unsafe mutations or replace reasoning with a blind script. The executor owns ordinary fixes through a coherent Candidate, requesting supplements only for a named gap. Internal test failures or partial progress alone do not call the orchestrator or reviewer; scope, authority, shared-contract, risk and actual budget boundaries still do. Use existing terminal waiting, not model polling; unsupported delivery retains its bounded LIMITED fallback.

Before the next suitable real task starts, retain its whole DOD, comparison task and scope differences in the existing measurement obligation. Include preparation, all executor sessions, model changes, failed attempts, handoff and management through required final/POST review, resulting corrections, retention and observed disposition, not merely owning acceptance. Until those obligations close, accounting is partial; later independent project Health is separate. Resolve changed/stopped task identity explicitly; never resume obsolete work to satisfy a measurement. Claim savings only from comparable accepted outcomes with attributable complete costs; otherwise report partial evidence. Steps, idle hours, packet size and installation are not task-cost savings. No synthetic replay or repeated acceptance for this measurement.

### Bounded Role Adoption
Use the accepted project-local model/effort mapping before default role hints. Keep vendor ids outside managed files. Retain the installed orchestrator and independent control profiles during an executor rollout; change either only at its own compatible owner-approved boundary. An update is not permission to downgrade active workers. Record task class, actual model/effort, supporting evidence and fallback in the existing routing record. A bounded benchmark does not prove general architecture, visual quality or independent-review capability. Without comparable evidence, retain the accepted profile. Preparation is optional when current context is sufficient.
When risk or an explicit requirement calls for final REVIEW, submit one coherent readiness Candidate for the whole useful outcome to the existing independent role in a context distinct from the producer. Bundle locally resolved fixes and proof; do not submit every intermediate edit. Required PRE/admission and renewed checks after material changes remain mandatory on the adopted route; see [mode selection](independent-control.md#select-and-prove-the-mode). A correction targets changed evidence and retained findings, not a new unrelated full review; final acceptance still covers the whole promised outcome. The orchestrator checks preparation sufficiency without a reviewer-of-preparer. The independent reviewer reads applicable originals and actual results, not only the author's summary; different model names alone do not prove independence.
Before the first substantive correction, use [Reframe After Failure](#reframe-after-failure), not an automatic model ladder. Retain the better verified candidate; the latest output does not supersede it by age. Escalation preserves current sources, negative findings, progress and prior spend.
At the owner's next natural safe checkpoint, apply through the ordinary updater and read back the installed kit and actual participant mapping. Do not interrupt an in-flight task or create a review solely to demonstrate a model switch. Validate on one suitable real task using existing acceptance, then retain its evidence limits. Account for preparation, execution, correction, review and coordination together; unknown usage stays UNKNOWN_NONZERO, not zero. Stop task follow-ups after actual acceptance and report delivery; do not periodically recheck an unchanged accepted result.

- The orchestrator owns purpose, scope, constraints, required Module Contracts,
  the question assigned to preparation, model/effort selection and packet review.
  It receives a concise evidence/gap/decision summary, not search transcripts.
  It preserves the accepted applicability and proof limits of donor modules in briefs and graph integration; a passed example is not permission to claim a reusable chain.
- The preparer finds and combines source-backed facts through map/index -> graph and public contracts -> released artifacts for consumption; maintainer design/code only for authorized development or an evidenced diagnostic question. It labels unread, unavailable and contradictory sources separately. It does not choose product direction, design a new solution, broaden authority, or declare history complete from a filename search.
- The executor implements and verifies the approved increment. It reads current code at the declared boundary and reports a real information gap via `CONSULT` to the orchestrator; it does not assign work or models to preparation itself.
- Preparation may draft index links or documentation from an exact Candidate
  and evidence under a bounded owner request. The executor incorporates and
  verifies required Module Contract changes before accepting that same Candidate.
  Post-task clerical work cannot defer required docs beyond acceptance. The
  orchestrator alone integrates shared meaning; new rationale is not clerical work.

Inspecting already authorized sources and edit/test paths is local execution, not a new preparation request. Reuse supplied contracts, citations and checks. Escalate only when these sources cannot answer a necessary question, disagree materially, or require an undeclared source/boundary. Retain progress and use the owner-approved supplement route. This does not expand packet access, authorize a new retrieval agent, or permit producer-source exploration for a consumed module.

User communication remains through the orchestrator: explain the useful result and next step, not internal routing. Preparation uses the existing focused-task lease, Return Sync and cleanup, never a permanent new manager or Guard loop.

## Reframe After Failure
Trigger on a substantive failed outcome, unexpected integration failure, repeated cause or preparation growing without outcome progress. Obvious local typos and expected red tests stay local; they need no consultant or new approval. Pause only the failing branch, preserve actual effects and the best verified candidate; UNKNOWN is not replay authority.
Before the first substantive correction, separate the accepted user outcome and necessary constraints from the chosen implementation. Trace only the relevant input -> transformation -> output -> consumer -> check, including adjacent public boundaries. Inspect authorized sources; broader diagnosis does not authorize closed-module internals or new access. Look wider, change less.
Classify the cause: input/contract, evaluator, integration/environment, approach, model capability or authority. Challenge the failed assumption with evidence. Consider at most two materially different alternatives, including the existing supported route or removal of an unnecessary dependency; never bypass an adopted protection boundary.
Keep six short fields in the existing brief/checkpoint, not a new report tree: outcome; observed failure and effects; failed assumption; new causal hypothesis; smallest changed plan and exclusions; discriminating check, owner, budget/checkpoint and stop condition. "Try harder" with the same plan is not a changed approach. Bound diagnosis within existing authority and budget; an unanswered boundary returns an exact gap, not another analysis round.
The same executor may make one bounded changed attempt under existing authority, preserving acceptance criteria and unaffected evidence. Source-bound findings retain independent disposition; an evaluator repair needs independent contract-based evidence and negative cases, never a weaker criterion just to pass. Verify changed and retained behavior; advice or a written rebrief alone is not recovery.
After that attempt fails, stop automatic redispatch for that cause. Distinguish a falsified hypothesis or missing input/access from a named reasoning/implementation capability gap. Only the latter justifies a stronger model/effort or specialist for that gap; preserve progress, original failure history and cumulative spend. A clear high-risk/capability gap may justify earlier escalation without a sacrificial weak attempt, within existing authority. Model, task id or wording changes do not reset attempts or grant more budget.
Local evidence inspection stays with the task. A fresh perspective uses existing owner-routed CONSULT/Discovery or REVIEW, only when needed: give goal, facts, failed hypothesis and relevant originals, not a duty to defend the executor's plan. Preparation supplies facts, not design. The orchestrator routes the decision, not product implementation; a consultant who designs or implements the repair cannot independently accept it. No permanent re-preparer, extra reviewer, scheduler or mandatory model call.
Use the existing Return/acceptance and memory route: close only on observed outcome, retain unresolved obligations, and end the failing episode with a supported next action or an exact owned wait. Independent safe work continues; material scope/trust changes and explicit pauses retain human control.

## Bounded Autonomous Assignment
An authorized autonomous assignment ends in accepted product evidence or an explicitly agreed, delivered request for a human decision; the latter leaves product DOD and ownership open. Define that distinction before starting, not retrospectively. Keep finite whole-task attempts, escalations and cost, a review/report reserve, actual cumulative usage and unknowns in the existing brief/ledger. New chats, causes, models and Goal ids do not refill them. Local debugging is not a separate attempt but still consumes the allowance. Use Reframe After Failure above, not a universal model ladder.

The owner invokes the existing independent reviewer at required acceptance, proposed substantive abandonment, or evidenced no-progress. Combine coincident subjects; no per-local-test review. The reviewer uses common principles, original constraints, exact artifacts, negatives, causal attempt history and spend, with addressable originals instead of the author's full conversation. It distinguishes measurable DOD/information progress, repetition of falsified hypotheses and concrete omitted checks. A correction must name the gap, useful changed hypothesis and discriminating check; "try harder" is not a verdict. Consultation means no justified authorized next action now, not proof that no alternative exists. A repair designer cannot independently accept its repair.

Before the dependent action, apply the evidence chain: review applicability -> real dispatch -> current scoped verdict -> owner application -> remaining authority. Reuse compatible evidence; stale bindings, missing review and an ACK alone cannot pass. A corrective verdict never expands budget, revives a rejected approach or resets attempts. Human pause, unsafe authority, unknown effects and hard caps stop affected activity without review; an unavailable reviewer leaves judgment pending, not success or an endless reviewer-recovery loop. Preserve independent safe work. Disagreements require contrary evidence, not shopping for an approving reviewer.

Use existing Action Receipt with `boundary:task-disposition` for a declared-evidence projection. Bind `work,owner,revision,candidate,plan,authority,ledger`, action (`execute/accept/handoff/halt`), pause/effects, authors, cumulative attempts and limits, plus the current `assignment` defined in the Responsibility Contract. `authority` is its original current human event, not an arrival or summary id. Budget supplies integer `limit,spent,reserved,next,reviewReserve` in one explicit unit; unknown totals cannot authorize execution. `review` records applicability/basis/triggers, dispatch, scoped verdict and application. CORRECT names gap/check, ACCEPT requires acceptanceEvidence, CONSULT requires grounds plus delivered handoff (retained work, alternatives, decisionNeeded, resumeWhen). `halt` needs no reviewer and never accepts product. See `evaluateTaskDisposition` and its scoped tests for the projection contract. PASS is consistency of supplied evidence, not authentication or permission.

An enrolled reference caller supplies `services.dispositionRequired:true` and `readTaskDisposition` from its existing authoritative task state. The callback binds task id/owner/hash and is re-read before commands; absence or non-PASS refuses dispatch. It must preserve ledger history and serialize/reserve budget through its existing authority. This helper does not authenticate sources, atomically reserve allowance, or intercept arbitrary native tools. Unenrolled callers retain legacy behavior, not a claim of protection. `dispositionRequired` on activity observations requires a matching receipt before routing a continuation; it is observation, not a host fence.

Native Goals may supply one continuation owner only when authorized and proven on that host. Do not stack it with Stop-hook loops or reminder timers. Respect actual native tool semantics for blocked/pause/budget/completion. Product Goal completion requires DOD; an explicitly bounded assignment Goal may finish only after its accepted result or agreed handoff is actually delivered. Never recreate it automatically after consultation. Missing lifecycle delivery, app shutdown, suppression of no-tool continuation or unsupported stopping remains scoped LIMITED; docs/API presence is not live proof. Retain the latest human pause even when an update asks for continuation. For other harnesses use their supported bounded mechanism, not an invented background guarantee.

## Fit With Existing Work

Mode names describe work, not automatic model assignments. Preparation locates known evidence; solution Discovery resolves what should be done with it.

| Situation | Route and completion |
| --- | --- |
| Current sufficient context | Direct execution; no preparer or additional approval. |
| Known evidence is scattered | Owner-scoped Preparation, checked packet, then its intended consumer. |
| Meaning or solution is unresolved | Bounded deep Discovery; preparation may supply facts, not the decision. |
| Experimental proof is needed | Lab keeps baseline, variable, conditions and cap; preparation finds prior evidence, never substitutes a fixture for real-flow proof. |
| Integration or repair | Map consume/change/create under the Module Contract: consume a fixed release through its public interface without producer-source reading; internal repair requires explicit change scope. Unknown design returns to Discovery, not guessed adapters. |
| Maintenance | Same routing by question; prove the original flow improved and return to it, not maintenance for its own sake. |
| Documentation and memory | Executor verifies required docs in the Candidate; orchestrator accepts reusable memory candidates. |
| Guard, update or rotation | Existing liveness/activation rules; no retrieval timer or forced model/worker restart. Carry pending consultations and human control forward. |

Lab is isolation, not a model tier: unresolved solution choices use Discovery; execution of an agreed experiment uses its proven execution profile or explicit human model choice. Its proof does not silently authorize production transfer.

Research starts with the known scope, authoritative sources, explicit gaps and a permitted report route; it does not need the complete implementation packet that it is supposed to discover. Missing inputs do not authorize dependent mutation. Do not recursively require preparation of preparation. Reuse a Discovery packet when sufficient for implementation; no automatic extra retrieval stage. An unresolved owner decision goes to that owner, not another search round. Preparation has its own bounded retrieval result/lease, not ownership of the implementation Candidate. While it runs, the affected executor waits on that named dependency; the preparer never waits on the same executor. Return consumption resumes the existing consumer under current authority, not a competing task. Respect direct human control: a supplement supplies facts, not a new direction.

## Initial Handoff and Later Gaps

1. The orchestrator sets a bounded question, source routes, required contracts,
   outcome, protected baseline and stop condition. The preparer returns facts,
   exact workspace-relative citations, gaps and a navigation packet. The owner
   reviews coverage, source meaning, citations and audience before confirmation.
   Invalid packets use the existing bounded repair/fallback path, not repeated
   full searches or delivery as if complete. Reuse valid findings on fallback.
2. A new implementation starts in a fresh executor without the preparer's transcript.
   The executor reads/acknowledges and starts authorized work in the same turn.
   Reuse the same worker for later supplements unless the authorized safe-boundary context pivot in `memory-recall.md` requires a fresh executor; preserve logical task, effects and spend, never replay finished work.
   Preparation for a manager/Discovery decision returns scoped evidence to that
   existing owner instead; it does not create an implementation task prematurely.
3. At a real gap, the executor reports the exact missing fact, affected operation
   and retained progress to the orchestrator. Continue independent safe work.
   The orchestrator distinguishes missing evidence, new solution design and
   environment failure; only bounded retrieval goes to cheap preparation.
4. The orchestrator approves a narrow supplementary question. The preparer
   returns an evidence delta; the owner incorporates it into a complete revised
   package retaining prior applicable constraints. A delta alone is not the task.
5. Confirm that package in a fresh output directory, then the authorized current worker reads
   and acknowledges it, continues, verifies retained and new behavior, and sends
   the current-task Return Sync. No new human checkpoint for an already authorized
   internal handoff. Changed scope/authority needs the ordinary rebrief instead.

Every navigation packet has `assignment` with exactly `owner`, `requestId`, `question`, `phase`, `previous`. Owner equals package owner; request id and question are nonempty. For `phase: "initial"`, `previous` is null. For `"supplement"`, it is `{plan:{path,sha256},approval:{path,sha256}}` pointing to the previous approved package. The builder checks those bytes, owner approval and exact task identity, worker, scope, action and Candidate files. Paths are workspace-relative.

Supplement input and output use new names; never overwrite predecessor evidence. Confirmation records `<previous-plan-path>.superseded.json` pointing to the exact successor. The supported `context-run` path rejects the old package and a competing successor; the new worker must acknowledge the new package. A failed confirmation is not permission to dispatch. Review its exact state and retry the same output; do not create parallel successors. These checks neither authenticate identities nor intercept arbitrary native edits; ordinary owner/lease control still applies.

## Cost Comparison

Use `agentRoutingPolicy.effortPolicy` over legacy profile fields. Orchestration uses flagship/Low; solution Discovery uses flagship/High. These are harness mappings, not model ids. A control failure means evidenced wrong routing, lost obligation or invalid readiness judgment. Reframe before one targeted correction; if that fails the same success criterion because of a named capability gap, use High for bounded recovery, not another blind Low retry. The existing escalation marker denotes this cause-qualified correction, not automatic promotion after any failure. Network/access failures, authorized pauses, missing human decisions and a worker's failing test alone do not trigger this escalation. Safety/authority uncertainty stops the affected action immediately; never try an unsafe action to earn a higher effort. Record the failure, correction, recovery criterion and effective effort in the existing next-action/State record. A High recovery ends only after observable handoff/return and retained obligations pass the criterion, not a promise or rewritten plan; return to Low at the next safe boundary. If High recovery still fails, use the existing blocker/confirmed-rotation path; do not oscillate Low/High, add retries or override human control. A missing switch capability has an explicit supported fallback/checkpoint, never a claimed switch. Independent work remains usable. Effort escalation never resets Guard repair limits, leases or burn caps: after a circuit breaker, High may diagnose/rebrief within authority, not replay the stopped action. Existing independent Governor anomaly evaluation is unchanged; routine checks remain model-free.

The orchestrator selects the lowest proven capable route for the task class, honoring explicit human choices and fallback. Prefer observed subscription usage when attributable; credit estimates are a secondary proxy, not allowance coefficients. Do not stop other work to measure account limits without permission. Until attributable allowance data exists, use dated credit-rate coefficients as the planning proxy, then calibrate against practical whole-chain usage and time to accepted result. Unknown costs remain unknown; no automatic model oscillation at checkpoints.

Use `node scripts/vydykhai.mjs context-prepare estimate --input cost.json` for an optional read-only comparison; it does not dispatch or authorize work. Input:

```json
{
  "schema": "context.cost.v1", "owner": "manager", "taskId": "task-1",
  "rates": [{"id": "current", "model": "resolved-model", "speed": "standard",
    "checkedAt": "2026-01-01", "source": "verified rate card",
    "input": 10, "cachedInput": 1, "output": 20}],
  "routes": [{"id": "prepared", "eligible": true, "evidence": "task-class proof",
    "stages": [{"purpose": "preparation", "rateId": "current", "effort": "low",
      "inputTokens": 1000, "cachedInputTokens": 500, "outputTokens": 100,
      "basis": "comparable observed task"}],
    "unknownCosts": ["remaining stages not measured"]}]
}
```

Numbers above are illustrative, not actual model rates. Rates are credits per million tokens with dated source and speed; record effort per stage. Include `preparation`, `execution`, `review`, `recovery`, `coordination`, and repeated turns; an omitted category produces PARTIAL. An inapplicable category may have zero tokens with an explicit reason, never a fabricated measurement. Cached input is a subset of total input; separately reported reasoning output is already included in output and must not be added again.

The calculation is `(input-cache)*inputRate + cache*cacheRate + output*outputRate`, divided by one million, summed over the chain. Compare only eligible routes; unknown costs prevent a cheapest-route claim. `subscriptionUsage: UNKNOWN` stays explicit. Capability, rate freshness, estimates and the final decision remain the owner's responsibility, not this calculator's.

The existing loop closes through source-backed context -> scoped work -> retained/new behavior and documentation review -> consumed Return -> integrated graph meaning and next action. Required docs/map links belong to the Candidate; required reusable memory stays an explicit owner obligation until integrated, not an implied side effect of delivery. Compare total effort and rework per accepted outcome, not activity counts. Repeated misses or rising coordination cost trigger existing Health Review/maintenance with proof of improvement on the original flow; no new timer, role or global memory rebuild.
