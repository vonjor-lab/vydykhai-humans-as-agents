# Accept Work

Check one task Candidate before claiming readiness. The task proves its accepted increment; the orchestrator routes the project response.

## Read route

Read `AGENTS.md` once and `docs/workflows/accept-work.md`. Load `docs/workflows/context-route.md` for applicable Memory Brief obligations, and `docs/workflows/memory-brief-envelope.md` only for a declared atomic envelope. `docs/FRAMEWORK.md` is a human overview for unresolved meaning, not a routine prerequisite.

## Boundaries

Compare the Accepted Baseline, current Candidate, module intent, latest human direction, complete applicable obligations and exact current-code evidence. Check affected risks and promised user loop, including independent consumer proof for packaging. Resolve ordinary failures inside scope; consult on new authority or module boundaries. A Lab pass does not grant production transfer.

## Finish

Use `docs/workflows/task-context-handoff-template.md#return-authorization` and the accept-work verdicts. Write the marked Return Sync to the authorized durable outbox before one permitted notification. Unknown external outcomes require reconciliation before replay. Readiness is evidence, not human acceptance or parent closure.
